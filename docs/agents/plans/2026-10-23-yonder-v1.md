# yonder v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single Go binary, `yonder <port>`, that makes `localhost:<port>` reachable from other devices on the LAN and prints the URL plus a terminal QR code.

**Architecture:** One `package main` at the repo root, one file per spec unit (`target`, `lan`, `port`, `proxy`, `wsl`, `main`). Pure functions take their inputs as arguments so tests need no real network; thin wrappers read the system. `main.go` wires them and owns all printing.

**Tech Stack:** Go 1.27, standard library, `github.com/mdp/qrterminal/v4`, goreleaser.

**Spec:** `docs/agents/specs/2026-10-23-yonder-design.md`

## Global Constraints

- Module path: `github.com/dpologdvinity/yonder`. Binary name: `yonder`.
- Only non-stdlib dependency: `github.com/mdp/qrterminal/v4` (it pulls `rsc.io/qr`).
- Every user-facing error is printed as `yonder: <message>` to stderr, exit code 1. Clean Ctrl-C exits 0.
- Default proxy port is `<port> + 10000`; fallback to an OS-chosen port if that is above 65535 or busy. `--listen N` busy is an error: `port N is in use`.
- Never call `ProxyRequest.SetXForwarded` and never set `X-Forwarded-Host`.
- Commits: Conventional Commits.
- Each task ends with `go vet ./... && go test ./...` green.

## Review Focus

1. A POST from the phone to a framework that checks `Origin` against `Host` (Next.js server actions) must succeed: upstream sees `Origin: http://localhost:<port>` and no `X-Forwarded-Host`. Test in Task 4.
2. Bad arguments (`yonder`, `yonder abc`, `yonder 0`, `yonder 70000`, `yonder 3000 4000`) print usage and exit 1, never panic. Test in Task 7.
3. The dev server restarts while yonder runs: requests during the gap get 502, and the next request after it comes back succeeds. Test in Task 4.
4. Server-sent events (webpack-hot-middleware HMR) must stream, not buffer. Test in Task 4.
5. A `Location` pointing anywhere other than the local target (OAuth redirect to `https://github.com/login`, relative `/dash`) must pass through unchanged. Test in Task 4.

### Task 4: `proxy`

**Files:**
- Create: `proxy.go`, `proxy_test.go`

**Interfaces:**
- Consumes: target address string from `findTarget`.
- Produces: `func newProxy(targetAddr string, port int) *httputil.ReverseProxy`.

Behavior:
- `Rewrite`: `SetURL` to `http://<targetAddr>`; `Out.Host = "localhost:<port>"`; if `Origin` header is set, replace it with `http://localhost:<port>`. No `SetXForwarded`.
- `ModifyResponse`:
  - `Location`: parse it; if absolute and its host is `localhost:<port>`, `127.0.0.1:<port>` or `[::1]:<port>`, replace scheme with `http` and host with `resp.Request` client host. The client host comes from the incoming request: carry it via a request context value set in `Rewrite` from `In.Host`. Anything else unchanged.
  - `Set-Cookie`: remove a `Domain=localhost` or `Domain=.localhost` attribute (case-insensitive), keep all other attributes.
- `ErrorHandler`: status 502, body `yonder: localhost:<port> is not responding\n`.
- Do not set `FlushInterval`; `ReverseProxy` already flushes `text/event-stream` immediately.

- [ ] **Step 1: Write the failing tests** (upstream is `httptest.NewServer`; front is `httptest.NewServer(newProxy(upstreamAddr, upstreamPort))`; requests set `req.Host = "192.168.1.20:13000"`):

  - `TestProxyOriginRewrite`: POST with `Origin: http://192.168.1.20:13000`; upstream sees `Origin == "http://localhost:<port>"` and `X-Forwarded-Host == ""`. (Review Focus 1)
  - `TestProxyLocationRewrite`: table. Upstream `Location: http://localhost:<port>/a` gives `http://192.168.1.20:13000/a`; same for `127.0.0.1` and `[::1]`; `https://github.com/login` unchanged; `/dash` unchanged. Client uses `CheckRedirect` returning `http.ErrUseLastResponse`. (Review Focus 5)

### Task 7: `main`: args, output, serve, shutdown

**Files:**
- Create: `main.go`, `main_test.go`, `e2e_test.go`

**Interfaces:**
- Consumes: everything above.
- Produces:
  - `var version = "dev"` (goreleaser sets it with `-X main.version=`).
  - `func parseArgs(args []string) (port, listenPort int, showVersion bool, err error)`. Accepts flags before or after the port: parse with a `flag.FlagSet` (`ContinueOnError`, output to `io.Discard`), take `fs.Arg(0)` as the port, then parse `fs.Args()[1:]` again. Valid ports are 1 to 65535. Anything left over is an error.
  - `func run(args []string, stdout, stderr io.Writer, ctx context.Context) int` returns the exit code; `main` calls `os.Exit(run(os.Args[1:], os.Stdout, os.Stderr, ctx))` with `ctx` from `signal.NotifyContext(..., os.Interrupt, syscall.SIGTERM)`.

`run` order: `parseArgs` (on error print usage to stderr, return 1); `--version` prints `yonder <version>`; `findTarget`; `systemLANAddrs` (empty means `no network connection found`); `listen`; print the output block from the spec (URL uses the first address and the listener's actual port; QR via `qrterminal.GenerateHalfBlock(url, qrterminal.L, stdout)`; other addresses listed under `also:`; then the warning line; then `detectWSLHint()` if non-empty); serve `withLog(newProxy(...), stdout, time.Now)` with `http.Server{Handler: ...}`; on `ctx.Done()` call `srv.Close()` (not `Shutdown`, which waits on hijacked connections) and return 0.

Usage text, exact:

```
usage: yonder <port> [--listen N]
       yonder --version
```
